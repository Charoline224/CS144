## 4 手动进行网络操作

现在开始使用网络。你将手动完成两项任务：获取一个网页（就像 Web 浏览器所做的那样），以及发送一封电子邮件（就像邮件客户端所做的那样）。这两项任务都依赖于一种称为**可靠双向字节流**的网络抽象：你会在终端中输入一系列字节，这些字节最终会以相同的顺序传递给另一台计算机上运行的程序（服务器）。服务器也会将自己的一系列字节传回你的终端。

### 4.1 获取网页

1. 在 Web 浏览器中访问 <http://cs144.keithw.org/hello>，观察结果。

2. 现在，你将手动完成浏览器所做的同一件事。

   **(a)** 在虚拟机中（或在自己的计算机上，例如 macOS 的“终端”程序中）运行：

   ```bash
   telnet cs144.keithw.org http
   ```

   这会让 telnet 程序在你的计算机与另一台名为 `cs144.keithw.org` 的计算机之间建立可靠字节流，并连接到该计算机上运行的特定“服务”——`http` 服务。HTTP 是超文本传输协议（Hyper-Text Transfer Protocol）的缩写，也是万维网所使用的协议。¹

   如果计算机设置正确且已连接互联网，你会看到：

   ```text
   user@computer:~$ telnet cs144.keithw.org http
   Trying 171.64.65.14...
   Connected to cs144.keithw.org.
   Escape character is '^]'.
   ```

   如果需要退出，请按住 **Ctrl**，同时按 **]**，然后输入 `close`。

   **(b)** 输入：

   ```http
   GET /hello HTTP/1.1
   ```

   （从第三个斜杠开始的那一部分。）这会告诉服务器 URL 中的**路径**部分。

   **(c)** 输入：

   ```http
   Host: cs144.keithw.org
   ```

   这会告诉服务器 URL 中的**主机**部分，即 `http://` 和第三个斜杠之间的部分。

   **(d)** 输入：

   ```http
   Connection: close
   ```

   这会告诉服务器你已经完成请求，服务器在完成回复后应立即关闭连接。

   **(e)** 再按一次 Enter 键。这会发送一个空行，告诉服务器你的 HTTP 请求已经结束。

   **(f)** 如果一切顺利，你会看到与浏览器中相同的响应，只不过前面会多出 HTTP **标头（headers）**，用于告诉浏览器应如何解释响应。

¹ 计算机的名称有一个数值等价物（`171.64.65.14`，即一个**互联网协议第 4 版地址**），服务名称也有一个数值等价物（`80`，即一个 **TCP 端口号**）。后面我们会进一步讨论这些内容。

### 4.2 给自己发送电子邮件

现在你已经知道如何获取网页，接下来使用同样的可靠字节流，向另一台计算机上运行的服务发送电子邮件。

1. 先 SSH 连接到 `sunetid@cardinal.stanford.edu`，以确保你处于 Stanford 网络中；然后运行：

   ```bash
   telnet 67.231.149.169 smtp
   ```

   ² `smtp` 服务指的是简单邮件传输协议（Simple Mail Transfer Protocol），用于发送电子邮件。如果一切顺利，你会看到：

   ```text
   user@computer:~$ telnet 67.231.149.169 smtp
   Trying 67.231.149.169...
   Connected to 67.231.149.169.
   Escape character is '^]'.
   220 mx0a-00000d07.pphosted.com ESMTP mfa-m0342459
   ```

2. 第一步：向邮件服务器标识你的计算机。输入：

   ```smtp
   HELO mycomputer.stanford.edu
   ```

   等待看到类似以下的响应：

   ```text
   250... Hello cardinal3.stanford.edu [171.67.24.75], pleased to meet you
   ```

3. 下一步：谁是邮件的发送者？输入：

   ```smtp
   MAIL FROM: sunetid@cs144.net
   ```

   将 `sunetid` 替换为你的 SUNet ID。³ 如果一切顺利，你会看到：`250 2.1.0 Sender ok`。

4. 接下来：谁是收件人？首先尝试给自己发送一封邮件。输入：

   ```smtp
   RCPT TO: sunetid@stanford.edu
   ```

   将 `sunetid` 替换为你自己的 SUNet ID。如果一切顺利，你会看到：`250 2.1.5 Recipient ok`。

5. 现在上传邮件正文。输入 `DATA`，告诉服务器你准备开始发送。如果一切顺利，你会看到：

   ```text
   354 End data with <CR><LF>.<CR><LF>
   ```

6. 现在你正在给自己写一封邮件。首先输入邮件客户端中会显示的**标头**。在标头末尾留一个空行：

   ```text
   354 End data with <CR><LF>.<CR><LF>

   From: sunetid@cs144.net

   To: sunetid@stanford.edu

   Subject: Hello from CS144 Lab 0!
   ```

² 这些说明在 Stanford 校外也可能有效，但我们无法保证。

³ 是的，发送者地址可以伪造。电子邮件有点像邮政系统中的实体邮件：回信地址的准确性（在很大程度上）依赖于诚信。你可以在明信片上填写任意回信地址，电子邮件基本上也是如此。请不要滥用这一点——这是认真的提醒。掌握工程知识也意味着承担责任！垃圾邮件发送者和犯罪分子经常使用伪造的发件人地址来冒充他人。你可以出于玩笑目的假装自己是 `santaclaus@northpole.gov`，但务必不要欺骗收件人。另外，即使收件人知情并参与玩笑，也不要发送冒充 Stanford 员工的邮件，否则可能触发学校的信息技术安全警报。

7. 输入邮件的**正文**——内容可以随意。完成后，在单独的一行输入一个句点结束：

   ```text
   .
   ```

   你应该会看到类似以下的响应：

   ```text
   250 2.0.0 33h24dpdsr-1 Message accepted for delivery
   ```

8. 输入 `QUIT`，结束与邮件服务器的会话。检查收件箱和垃圾邮件文件夹，确认是否收到邮件。

### 4.3 监听和连接

你已经通过 telnet 体验了客户端能够做什么：客户端可以向运行在其他计算机上的程序发起连接。现在让我们尝试充当一个简单的服务器——一种等待客户端连接的程序。

1. 在虚拟机的一个终端窗口中运行：

   ```bash
   netcat -v -l -p 9090
   ```

   你应该会看到：

   ```text
   user@computer:~$ netcat -v -l -p 9090
   Listening on [0.0.0.0] (family 0, port 9090)
   ```

2. 保持 netcat 运行。在另一个终端窗口中（同样是在虚拟机中）运行：

   ```bash
   telnet localhost 9090
   ```

3. 如果一切顺利，netcat 会打印类似以下内容：

   ```text
   Connection from localhost 53500 received!
   ```

4. 现在尝试在任意一个终端窗口中输入内容——无论是 netcat（服务器）窗口还是 telnet（客户端）窗口。注意：你在一个窗口中输入的任何内容都会出现在另一个窗口中，反之亦然。你需要按 Enter 键，字节才会被传输。

5. 在 netcat 窗口中输入 **Ctrl-C** 退出程序。注意 telnet 程序也会立即退出。

## 5 使用操作系统流式套接字编写网络程序

在本次预热实验的下一部分，你将编写一个从互联网获取网页的短程序。你会使用 Linux 内核以及大多数其他操作系统提供的一项功能：在两个程序之间建立**可靠双向字节流**的能力。其中一个程序运行在你的计算机上，另一个程序运行在互联网另一端的计算机上，例如 Apache 或 nginx Web 服务器，或者 netcat 程序。

这项功能称为**流式套接字（stream socket）**。对于你的程序和 Web 服务器来说，套接字看起来就像普通的文件描述符（类似于磁盘上的文件，或 stdin/stdout 输入输出流）。当两个流式套接字连接后，写入一个套接字的任何字节，最终都会按照相同顺序从另一台计算机上的另一个套接字中读出。

然而，实际上互联网并不提供可靠字节流服务。互联网真正提供的只是“尽力而为”地把称为**互联网数据报（Internet datagram）**的短数据片段发送到目的地。每个数据报都包含一些元数据（标头），说明源地址和目标地址等信息——数据报来自哪台计算机、要发送到哪台计算机——以及要交付给目标计算机的有效载荷数据（最多约 1,500 字节）。

尽管网络会尽量传送每个数据报，但在实际中，数据报可能会：

1. 丢失；
2. 乱序到达；
3. 内容被修改；
4. 被重复传送并到达多次。

通常，连接两端的操作系统负责将“尽力而为的数据报”（互联网提供的抽象）转换成“可靠字节流”（应用程序通常需要的抽象）。

两台计算机必须相互协作，确保字节流中的每个字节最终都能按正确顺序传递到另一端的流式套接字。它们还必须相互告知自己准备接收多少数据，并确保发送方不会发送超过接收方愿意接受的数据量。所有这些工作都通过一种在 1981 年制定的约定方案完成，这就是**传输控制协议（Transmission Control Protocol，TCP）**。

在本实验中，你只需要使用操作系统已经提供的 TCP 支持。你将编写一个名为 `webget` 的程序，它创建 TCP 流式套接字，连接到 Web 服务器并获取网页——这与本实验前面手动完成的操作类似。在未来的实验中，你将实现这个抽象的另一端：自己实现传输控制协议，从不太可靠的数据报中构造可靠的字节流。

### 5.3 现代 C++：大体安全，同时保持快速和底层

CS144 是一门编程比重很大的课程。实验作业采用现代 C++ 风格，使用较新的（2023）语言特性，以尽可能安全的方式编程。这种风格可能不同于你过去学习 C++ 时被要求采用的方式。关于这种风格的参考资料，请参见 C++ Core Guidelines：<http://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines>。

基本思想是：确保每个对象都具有尽可能小的公开接口，包含大量内部安全检查，不容易被错误使用，并且能够负责清理自身资源。我们希望避免“成对”的操作（例如 `malloc/free` 或 `new/delete`），因为成对操作的第二步可能无法执行（例如函数提前返回或抛出异常）。相反，应当在对象的构造函数中执行资源获取操作，在析构函数中执行对应的释放操作。这种风格称为**资源获取即初始化（Resource Acquisition Is Initialization，RAII）**。

具体来说，我们希望你做到以下几点：

- 使用 <https://en.cppreference.com> 上的语言文档作为参考。（我们建议避免使用更容易过时的 cplusplus.com。）
- 永远不要使用 `malloc()` 或 `free()`。
- 永远不要使用 `new` 或 `delete`。
- 基本上不要使用裸指针（`*`）；只有在必要时才使用“智能”指针（`unique_ptr` 或 `shared_ptr`）。（在 CS144 中你不需要使用这些智能指针。）
- 避免使用模板、线程、锁和虚函数。（在 CS144 中你不需要使用它们。）
- 避免使用 C 风格字符串（`char *str`）或字符串函数（`strlen()`、`strcpy()`）。它们很容易出错，请使用 `std::string`。
- 永远不要使用 C 风格类型转换，例如 `(FILE *)x`。如果确实需要类型转换，请使用 C++ 的 `static_cast`（一般而言，在 CS144 中你不需要进行这种转换）。
- 函数参数优先使用 `const` 引用传递，例如：`const Address & address`。
- 除非变量需要被修改，否则将每个变量声明为 `const`。
- 除非方法需要修改对象，否则将每个方法声明为 `const`。
- 避免使用全局变量，并让每个变量的作用域尽可能小。
- 提交作业前，运行以下命令：

  ```bash
  cmake --build build --target tidy
  ```

  该命令会提出与 C++ 编程实践有关的改进建议；然后运行：

  ```bash
  cmake --build build --target format
  ```

  以统一代码格式。

## 6 内存中的可靠字节流

到目前为止，你已经看到：即使互联网本身只提供“尽力而为”的不可靠数据报服务，**可靠字节流**这一抽象仍然可以有效地用于互联网通信。

在本周实验的最后，你将在单台计算机的内存中实现一个提供这一抽象的对象（你可能已经在 CS 110/111 中做过类似的事情）。字节会从“输入”端写入，并以相同的顺序从“输出”端读出。字节流是有限的：写入者可以结束输入，之后不能再写入更多内容。当读取者读到流的末尾时，会到达 EOF（文件结束），之后不能再读取更多内容。

---

你的字节流还必须具备**流量控制**功能，以限制任意时刻的内存消耗。对象初始化时会指定一个“容量”：也就是它在任意时刻愿意保存在自身内存中的最大字节数。字节流会限制写入者每次能够写入的数据量，从而确保流不会超过存储容量。当读取者读取字节并将其从流中移除后，写入者就可以继续写入更多字节。你的字节流只会在单个线程中使用，因此不必考虑并发读写、锁或竞态条件。

需要明确的是：字节流虽然是有限的，但在写入者结束输入并完成流之前，它可以几乎任意长。⁴ 你的实现必须能够处理远大于容量的流。容量限制的是某一时刻保存在内存中的字节数（已经写入但尚未读取的字节），并不限制整个流的长度。一个容量只有 1 字节的对象仍然可以传输数万亿字节的数据，只要写入者每次写入 1 个字节，并且读取者在写入者能够继续写入之前读取掉该字节即可。

以下是写入端的接口：

```cpp
void push( std::string data ); // 将数据推入流中，但只能推入当前可用容量允许的部分。
void close();                 // 表示流已经到达末尾，不会再写入任何内容。

bool is_closed() const;              // 流是否已经关闭？
uint64_t available_capacity() const; // 当前可以推入流中的字节数
uint64_t bytes_pushed() const;       // 累计推入流中的总字节数
```

以下是读取端的接口：

```cpp
std::string_view peek();       // 查看缓冲区中的下一个字节
void pop( uint64_t len );      // 从缓冲区中移除 len 个字节
bool is_finished() const;      // 流是否已经结束（已关闭且所有内容都已弹出）？
bool has_error() const;        // 流是否发生过错误？
uint64_t bytes_buffered() const; // 当前缓冲的字节数（已推入但尚未弹出）
uint64_t bytes_popped() const;   // 从流中累计弹出的总字节数
```

请打开 `src/byte_stream.hh` 和 `src/byte_stream.cc` 文件，实现一个提供上述接口的对象。在开发字节流实现时，可以使用以下命令运行自动化测试：

```bash
cmake --build build --target check0
```

如果所有测试都通过，`check0` 测试随后还会运行一个速度基准测试。对于本课程的要求，针对所测试的三种 `pop` 长度，只要速度快于 0.1 Gbit/s（即每秒 1 亿比特）即可接受。（某些实现可以达到超过 10 Gbit/s 的速度，但这取决于计算机的速度，课程并不要求达到这一水平。）

如果出现最新问题，请查看课程网站上的实验 FAQ，或在实验课中向同学或教学团队提问，也可以在 EdStem 上提问。

⁴ 至少可以达到 2⁶⁴ 字节；在本课程中，我们将其视为基本上任意长。
